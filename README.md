# HackFlow

HackFlow — веб-платформа для организации хакатонов, формирования команд, подачи проектов и их оценки судьями.

## Возможности

### Участник
- Просмотр опубликованных хакатонов.
- Создание команды и приглашение зарегистрированных пользователей по email.
- Редактирование проекта команды и отправка проекта на оценивание.

### Организатор
- Создание и редактирование черновиков хакатонов.
- Настройка критериев оценки до публикации.
- Публикация и отмена хакатонов.
- Назначение зарегистрированных пользователей судьями по email.
- Просмотр оценок, итоговых баллов и рейтинга проектов.

### Судья
- Просмотр назначенных хакатонов и поданных проектов.
- Сохранение черновика оценки по критериям.
- Окончательная отправка оценки; отправленная оценка блокируется от дальнейшего редактирования.

В рейтинг включаются только окончательно отправленные оценки. Проект без завершённых оценок не получает итогового места.

## Технологии

- **Frontend:** React 19, TypeScript, Vite.
- **Backend:** Node.js, Express 5, TypeScript.
- **База данных:** PostgreSQL 17, Prisma 7.
- **Авторизация:** JWT в HttpOnly cookie, хеширование паролей через bcrypt.
- **Почта для локальной разработки:** Nodemailer и Mailpit.
- **Запуск инфраструктуры:** Docker Compose.

## Требования

- Windows 11 или другая ОС с поддержкой Node.js и Docker.
- Node.js 24 (рекомендуемая версия для проекта).
- npm.
- Docker Desktop с запущенным Docker Engine.
- Git — если проект клонируется из репозитория.

## Локальный запуск в Windows PowerShell

Все команды ниже выполняются из каталога проекта `C:\Projects\hackflow`, если не указано иное.

### 1. Подготовить переменные окружения

Создайте локальный файл `.env` на основе шаблона:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и проверьте настройки. Обязательно замените `JWT_SECRET` на случайную строку длиной не менее 32 символов. Значение `DATABASE_URL` должно соответствовать параметрам `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` и `POSTGRES_PORT`.

Файл `.env` содержит локальные настройки и секреты — не добавляйте его в Git. Для примера настроек предназначен `.env.example`.

### 2. Запустить PostgreSQL и Mailpit

Из корня проекта выполните:

```powershell
docker compose up -d db mailpit
docker compose ps
```

Настройки портов по умолчанию:

| Сервис | Адрес | Назначение |
|---|---|---|
| PostgreSQL | `127.0.0.1:5432` | База данных |
| Mailpit SMTP | `127.0.0.1:10250` | Локальная отправка почты |
| Mailpit Web UI | <http://127.0.0.1:8025> | Просмотр писем в разработке |

### 3. Установить зависимости и подготовить базу данных

Откройте отдельный терминал PowerShell:

```powershell
Set-Location C:\Projects\hackflow\server
npm install
npx prisma generate
npx prisma db push
```

Команда `prisma generate` генерирует Prisma Client, используемый сервером. Команда `prisma db push` синхронизирует локальную базу с текущей Prisma-схемой. Она подходит для локальной разработки; для production-среды следует использовать контролируемую стратегию миграций.

### 4. Запустить backend

В том же терминале, находясь в каталоге `server`, выполните:

```powershell
npm run dev
```

По умолчанию API доступен по адресу `http://127.0.0.1:3001`.

Проверка доступности API и базы данных:

```powershell
Invoke-RestMethod http://127.0.0.1:3001/api/health
Invoke-RestMethod http://127.0.0.1:3001/api/health/db
```

Для успешного подключения endpoint базы данных должен сообщать, что соединение установлено.

### 5. Запустить frontend

Откройте ещё один терминал PowerShell:

```powershell
Set-Location C:\Projects\hackflow\client
npm install
npm run dev -- --host 127.0.0.1
```

Откройте приложение в браузере: <http://127.0.0.1:5173>.

## Сборка проекта

Сервер и клиент собираются отдельно.

### Backend

```powershell
Set-Location C:\Projects\hackflow\server
npm run build
```

### Frontend

```powershell
Set-Location C:\Projects\hackflow\client
npm run build
```

Успешная сборка клиента включает проверку TypeScript и production-сборку Vite.

## Основной пользовательский сценарий

1. Зарегистрируйте пользователя и войдите в HackFlow.
2. Организатор создаёт хакатон, задаёт критерии и публикует мероприятие.
3. Участник создаёт команду, приглашает участников, подготавливает и отправляет проект.
4. Организатор назначает зарегистрированных пользователей судьями.
5. Судьи сохраняют черновики оценок и окончательно отправляют их.
6. Организатор открывает панель результатов и просматривает оценки и рейтинг.

Письма, отправленные в локальной среде, можно просматривать в Mailpit: <http://127.0.0.1:8025>.

## Полезные замечания

- Frontend и backend запускаются в отдельных терминалах.
- Локальная конфигурация находится в корневом `.env`; не публикуйте секреты или реальные пароли.
- При изменении структуры `server/prisma/schema.prisma` для локальной разработки обновите базу данных командой `npx prisma db push` и сгенерируйте Prisma Client командой `npx prisma generate`.
- Команда `npm test` пока не настроена как автоматизированный набор тестов. Для текущей проверки используйте сборки клиента и сервера, health endpoints и сценарии в интерфейсе.
